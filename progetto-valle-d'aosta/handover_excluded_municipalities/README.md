# Handover: Hard-to-Forecast Municipalities

This folder is a **self-contained working package** for a collaborator. The task is to
**find appropriate forecasting models** for a small set of Valle d'Aosta municipalities
that the main project pipeline could not forecast reliably.

You do **not** need to understand the whole repository to start. This folder gives you
(1) the background you need, (2) a script that loads the data for these municipalities, and
(3) ready-to-use CSVs.

---

## 1. Background (what the wider project does)

The parent project studies **how tourism pressure drives municipal electricity demand**
in Valle d'Aosta, using a monthly panel of 74 municipalities (Jan 2015 – Sep 2025). The
modelling pipeline has three blocks:

1. **Mean effect** — mixed-effects models of log electricity demand on log tourist arrivals.
2. **Tail risk** — copulas measuring where tourism and electricity *extremes* co-occur.
3. **Forecasting & scenarios** — a regional tourism forecast (NNAR) is allocated to
   municipalities, and per-municipality electricity models translate tourism scenarios into
   load forecasts.

The **forecasting block** assigns each municipality the best of several candidate models
(Mixed-effects, GAMM, Prophet) based on 2025 out-of-sample accuracy.

## 2. Why these municipalities were set aside

During model selection, every candidate model produced a **validation MAPE above 20%** on the
2025 window for the municipalities below, so they were **flagged as "anomalous" and excluded**
from the production forecast/scenario step (they are still used in the historical mean-effect
and tail-risk analyses). They tend to be **small, high-seasonality mountain comuni** with sparse
and spiky arrivals, where regional-share allocation and the standard models break down.

The original record of this exclusion lives in the main repo at
`Modelli/Forecast/results/scenario_forecast/tourism_shock_anomalous_excluded_towns.csv` and
`Modelli/Forecast/results/intermediate/anomalies/towns_anomalous_mape_gt20_2025.csv`.

### The 11 excluded municipalities (best-model 2025 validation MAPE)

| Municipality | comune_key | Best model so far | Best MAPE % |
|--------------|-----------|-------------------|-------------|
| Valpelline | valpelline | Prophet | 239.9 |
| Allein | allein | Prophet | 80.9 |
| Valgrisenche | valgrisenche | Mixed | 59.8 |
| Pont-Saint-Martin | pont saint martin | Prophet | 59.6 |
| Avise | avise | Prophet | 49.7 |
| Bionaz | bionaz | Mixed | 49.2 |
| Saint-Denis | saint denis | Mixed | 39.9 |
| La Magdeleine | la magdeleine | Prophet | 31.1 |
| Doues | doues | GAMM | 23.3 |
| Rhêmes-Notre-Dame | rhemes notre dame | GAMM | 22.0 |
| La Thuile | la thuile | Prophet | 21.0 |

These MAPE values are the **current bar to beat**: any model with a lower 2025 MAPE is an
improvement.

> Note: Rhêmes-Notre-Dame and La Thuile also appear prominently in the project's *tail-risk*
> ranking. That is consistent — tail risk is an in-sample historical diagnostic, whereas the
> exclusion above is purely about *forward forecast* reliability.

## 3. Your task

For each municipality, **find a forecasting model that predicts monthly tourist arrivals
(`totale_arrivi`) well out of sample** (and, if useful, the electricity series `kwh`). You are
free to use any approach: tailored ARIMA/ETS, Prophet with custom seasonality/holidays,
intermittent-demand methods (Croston, ADIDA), hierarchical reconciliation, GAMs, etc. The aim
is a per-municipality model that beats the MAPE bars in the table above on the 2025 window.

## 5. How to run

The source data (`data_full.csv`) is **already bundled in this folder**. The script tries hard
to find it automatically. The most reliable ways to run it:

- **RStudio (recommended):** open `load_excluded_municipalities.R` from this folder and click
  *Source* (the whole file runs at once and finds the bundled data automatically).
- **Terminal:** from inside this folder, run:

  ```powershell
  Rscript load_excluded_municipalities.R
  ```

- **R console:** set the working directory to this folder first, then source it:

  ```r
  setwd("C:/path/to/handover_excluded_municipalities")  # <-- this folder
  source("load_excluded_municipalities.R")
  ```

> **Important — don't paste the script line-by-line into the console.** A pasted script cannot
> know where the `.R` file lives, so if your console's working directory is somewhere else (e.g.
> `Documents`) it won't find the bundled `data_full.csv`. Use *Source* in RStudio, or `setwd(...)`
> first, or `Rscript` as above.
>
> If the data still isn't found in an **interactive** session, the script now opens a **file
> dialog** so you can simply click `data_full.csv` yourself. You can also hard-code the path by
> setting `data_path_manual` at the very top of the script.

Required R packages: `dplyr`, `lubridate`.

After running, you get the CSVs in `data/` plus these in-session objects:

- `panel` — all excluded municipalities (long format),
- `panel_by_comune` — a named list, one tibble per municipality,
- `coverage` — months available and non-missing counts per municipality.

## 6. Data dictionary (key columns)

Each row is one **municipality × month**. The most relevant columns:

| Column | Meaning |
|--------|---------|
| `comune_key`, `comune_nome` | Municipality id / name |
| `date`, `year`, `month_num` | Month timestamp and parts |
| `totale_arrivi` | Monthly tourist **arrivals** (main forecast target) |
| `totale_presenze` | Monthly tourist **overnight stays** |
| `numero_alloggi`, `numero_letti` | Accommodation supply (units, beds) |
| `residenti` | Resident population |
| `kwh` | Monthly municipal electricity consumption |
| `temperatura`, `precipitazione`, `pressione`, `umidit_relativa` | Monthly weather |
| `log_arrivi`, `log_kwh` | `log1p` transforms added by the loader for convenience |

Each municipality has ~129 monthly observations (Jan 2015–Sep 2025). To mirror the project's
evaluation, **train on data up to Dec 2024 and validate on Jan–Sep 2025** using MAPE.
